# Body OS｜MVP 埋点

> 这份清单原来只是「打算埋哪些」。**现在按代码里的实际情况标了 ✅ / 未做** —— 否则它读起来像个承诺,
> 而漏掉的埋点是**静默**的:分母少一块,漏斗照样出数,没人会发现。
> ✅ 的口径是「**代码里确实调了这个名字**」(用下面的 grep 逐个核过),不表示埋的位置一定对。
> 核对办法:`grep -rhoE "track(N|Now)?\('[a-z_]+'" app/src` 只能查出**字面量**调用;
> 激活那一组是走 `EVENT` 映射的(见下),用名字 grep 会漏,要查 `markFirst`。

## 激活 ✅（全部已实现,收口在 `app/src/utils/activation.ts` 的 `markFirst`）
- onboarding_start ✅
- onboarding_complete ✅
- first_food_log ✅
- first_activity_log ✅
- first_weight_log ✅
  - 这三条**不是**在页面里点名上报的,而是在 `services/{food,activity,body}.ts` 的写入函数里各调一次 `markFirst(kind)`
    —— 入口今天有两个(记录页 / 快捷记录),以后还会多;写一次漏一处的代价不是少一个数,是漏斗分母永远对不上。
  - 「第一次」由**storage 里的名单**判定(`bodyos.activation.first`),所以重启不会重复报;名单是逐台设备记的,
    真要看人唯一次的漏斗得在服务端按 userId+event 去重。
  - 三条各自独立:记了饭不等于激活了体重;只量围度**不算**记体重(`weightKg` 才是那个信号)。
  - 上报走**可重试的队列**(`track`,切后台 flush),不是 `trackNow` —— 攒够一次一并传。

## 首页
- home_view ✅
- body_score_view 不埋 —— 身体分数没有独立查看入口,只是首页概览里的一个数;
  无交互可埋。哪天做了独立的「身体报告」页再立这个事件。
- daily_ai_click ✅（名字沿用文档里的旧名）
- daily_ai_regen ✅ —— 解读卡上的「重新生成」。和 daily_ai_click 的差值 =
  「看完一次还想再看」的量,是解读有没有用的最低限度信号。
- daily_action_click 不埋 —— 解读里的「建议行动」目前是**纯展示**(`insight.actions` 渲染成文本,
  没有可点的目标)。等行动条做成可点(点了进对应记录页)再埋,现在埋不出来。
- `home_training_click` ✅ / `home_training_resume` ✅ / `home_training_resume_drop` ✅ / `home_training_off` ✅
  —— 首页那张「今天练什么」卡上的四个出口。前三条早就在了;
  `home_training_off`(卡片上那条「今天不练」)与 `training_day_off`(真的记下了一天请假,在计划页)——
  另外 `home_training_switch`(卡片上那条「今天改练」):它和 `home_training_off` 是一对,
  两条点击量的比就是「今天该练的日子,有多少人觉得说的不对」里「不练」和「换一套」各占多少
  是一对:**入口点了几次**和**假条真的记下了几条**,中间的差值就是「点开又反悔」——
  只埋其中一条的话,这个差值永远看不见
- `home_date_switch` ✅ —— 顶部日期条切到别的日子。看的是「回看昨天」有多少:
  当天忘记记录、第二天补看是记录类产品的常见节律。

## 训练（后加的一整套,补记在这里;都在 `pkg-exercise` 里）
- 计划:`training_plan_view` / `training_plan_create` / `training_plan_edit` / `training_plan_share_view` /
  `training_plan_share_copy` / `training_plan_import_add` / `training_plan_import_replace` / `plan_delete` /
  `training_day_dup`(复制一个训练日 —— 只有编排页那一个入口,点一下记一次)
- 训练执行:`training_workout_start` / `training_workout_done` / `training_exercise_history` / `training_muscles` / `training_stats` /
  `training_log_history`(全部训练记录)
- `training_muscles_to_lib`(肌群页点「练得到背的动作 ›」,带 `{ group }`)——
  这一页唯一的出口,点它的人多,说明「说完结论还得自己走过去找动作」这个顾虑是真的
- `training_muscles_metric`(肌群页切「组数怎么算」,带 `{ metric: 'all' | 'hard' }`)——
  看的是有多少人切到「只看有效组」:切的人少,说明「有效组」这个概念要么没讲清、要么没人在意;
  切了又切回去的人多,说明门槛或文案有问题(切换本身是**要能**看出来的,不然那张卡就是个装饰)
- `training_heat_metric`(统计页切热力图色阶口径,带 `{ metric: 'sets' | 'minutes' | 'volume' }`)——
  和肌群页那个开关同一个问题:切的人少说明「同一张格子图能看三件事」没讲清(标题旁边那排开关不够显眼),
  只切到「时长」不再动的人多,说明组数那档的门槛不合他(3 组以内算摸了一下,对高次数的人偏低)
- 记录:`training_log_edit` / `training_log_edit_save` / `training_log_backfill` / `training_log_backfill_save`
- 训练中的临时改动(都不动计划本身):`training_duration_open` / `training_duration_edit`(手改单堂时长) /
  `training_add_set`(加一组) / `training_add_exercise`(加练一个动作) /
  `training_rest_pause`(按了暂停 —— **只记按下那一下,继续不记**:有暂停就一定有继续,
  两条一对把分母算两遍;要看的是「有多频繁被打断」,次数多说明那一档组间休息对这个人偏短,
  是回去调计划的信号,不是他在训练页多按了一个键) /
  `training_row_noprog`(把某个动作标成「这次不算进步」—— 同样只记**标上**那一下,取消不记。
  这个数高得离谱的话,要问的不是「用户为什么总在排除动作」,而是**渐进规则对这个场景不适用**:
  器械换来换去、重量不可比是常态,那该改的是强度台阶或组间休息的建议,不是让他每次手动排除)
- 动作库:`exercise_lib_view`(打开动作库) / `exercise_lib_detail`(点开某个动作) / `exercise_star`(收藏) /
  `exercise_add_plan`(从动作库把一个动作加进计划 —— 记的是**点了这个入口**,不是加成功那一刻;
  两者之间的差别就是我们要看的「选完训练日又放弃」)
- 自助动作:`custom_ex_view` / `custom_ex_save` / `custom_ex_delete` / `custom_ex_delete_undo`
- 器材与提醒:`kit_view` / `reminder_view`
- 数据:`training_backup_export` / `training_backup_import` / `sync_view` / `training_share_view`
- 训练 tab(主包那页,「开练台」):`training_tab_view` / `training_tab_resume {sets}` /
  `training_tab_switch`(今天改练)/ `training_tab_off`(今天不练)—— 和首页那张卡的四个同名事件
  是**两个入口同一组动作**,两边对得上才看得出哪个入口在用。
- 练前称重:`training_weigh_open` / `training_weigh_save`(训练页顶部「练前上称」)
- 肌群探索:`training_muscle_explore` / `training_muscle_explore_pick {group}` /
  `training_muscle_explore_to_ex {exerciseId}` / `training_muscle_explore_to_plan {exerciseId}`
- 本地教练(纯客户端问卷,无识别调用):`training_coach_view` / `training_coach_proposal` /

  3 条、全会话最多 20 条 —— 它是排查信号不是精确计数。服务端 `GET /analytics/client-errors`
  (x-admin-key)直接看最近七天,不用登库裸查。
